# Paper C 验证计划与检查点

> 每一步都写明“跑什么、看什么、过线标准”。未过线时按“退路”处理，不硬推。所有指标报 1,000 次 Bootstrap 95% 置信区间。

## V0 查新（不依赖数据，可先做）
- 检索：并行分支分解 vs 思维链、推理链到并行原语的蒸馏、分支级 / 子问题级升级、清单式 VLM 安全评估。
- 过线：没有人同时做“共享预填充的并行判别原语 + 结构化有序聚合 + 分支级升级”。
- 退路：若已有高度重合工作，把主贡献收窄到“行业条件结构化聚合 + 分支级升级”，并把对方作为基线。

## V1 数据核对（数据下完后第一件事）
- 跑 `scripts/build_index.py`，检查：
  1. 训练 / 测试样本数是否为 3,763 / 1,250，测试异常是否为 251。
  2. 各安全等级的数量（原文没给）。
  3. 文件夹名中的 `LevelXX` 与描述文本最后一行的等级是否一致（脚本会输出一致率）。
  4. 行业前缀是否全部映射到五个行业（脚本会列出未映射前缀，补进 `configs/inspecsafe_taxonomy.json`）。
- 过线：标签解析失败率 < 1%。
- 已知（10/15 从测试集文件夹名统计）：测试集 251 张异常中 Level one 169、Level two 75、**Level three 只有 7**。
  Level three 相关的任何指标置信区间都会很宽，正文以“异常 vs 正常”和“高危（Level one/two）漏报”为主，
  Level three 只在附录报告。
- 描述文本格式是一句话，结尾为 “Therefore, the safety level is Grade One.” 或 “..., no abnormalities observed.”，
  并直接列出隐患（如 “hazards include smoking, not wearing a safety helmet, and not wearing gloves”），
  适合直接做 V6 的分支弱标签。
- **V1 结果（10/15，已通过）**：5,013 条（训练 3,190 / 验证 573 / 测试 1,250），等级全部解析成功，
  文件夹 `LevelXX`、Normal/Anomaly 目录与文本标签 100% 一致，五个行业全部映射。
- **弱标签检查（V6 前置，`scripts/check_weak_labels.py`）**：描述文本抽取的隐患 + 行业判据表推出的等级，
  与真值一致率 96.8%（Level one 98.5%、Level two 98.2%、正常 96.5%）。发现：
  1. 冶金正常场景常描述“渣罐旁冒烟”（工艺烟雾）却标为正常——烟雾原语的问题已改为“忽略正常工艺烟雾 / 蒸汽”，
     这类样本也是检验分支是否会误报的好用例。
  2. 少量标注与官方判据表不一致（如油气化工“玩手机”标为一级、隧道“未戴安全帽”标为一级，表中均为二级）。
     说明可以考虑用训练集数据修正行业严重度表，而不是完全照搬官方表（作为 V4 的一个消融）。

## V2 快模型基线（S1 直接问等级）
- `scripts/run_direct.py`：Qwen3-VL-8B-Instruct，四选一，读四个选项的概率。
- 看：准确率、Macro-F1、QWK、ECE、代价敏感 RPS、高危漏报率、正常样本误报率。
- 用途：所有比较的起点。

## V3 慢模型基线（S2 Thinking）
- `scripts/run_thinking.py`：Qwen3-VL-8B-Thinking，用官方提示，保存完整推理过程。
- 看：与 V2 的差距（预期约 8 个点）、救回数、误伤数、输出 token 数与耗时。
- 过线：S2 − S1 ≥ 3 个点（否则“快慢差距”本身不成立，需要换更强 S2，如 Qwen3-VL-32B）。

## V4 核心假设：并行原语能追回多少差距（10/22 go/no-go 主实验）
- `scripts/run_fanout.py` + `scripts/evaluate.py`。
- 比较：V2（直接问）、V4a（分支 + 未校准 noisy-OR）、V4b（分支 + 验证集校准）、V3（Thinking）。
- 过线（满足任一即 go）：
  1. V4b 追回 S1 → S2 差距的 ≥ 50%，且单图推理耗时 ≤ S2 的 1/5；
  2. V4b 的代价敏感风险（高危漏报加权）显著低于 V2（置信区间不重叠）。
- 重点检查：正常样本误报率。分支越多，noisy-OR 越容易累积误报；若误报率比 V2 高出 5 个点以上，先检查分支校准与泄漏项 λ_k。
- 退路：若 V4b 不及 V2，看分支逐项准确率，定位是“个别隐患问不准”还是“聚合规则错”，再决定改提示还是改聚合。

## V5 分支级升级
- 需要 S2 对分支的核验答案：`run_fanout.py --model <Thinking>` 只跑 V4 中被选中的分支（按预算 10% / 20% / 30%）。
- 比较同等慢模型调用成本下：整图级升级（MSP、熵、SRR 式路由）vs 分支级升级（信息价值排序）。
- 过线：同等成本下，分支级升级的准确率或代价敏感风险优于整图级，且误伤数更少。

## V6 推理链到分支的蒸馏（11 月）
- 先用 `ideas/chain_to_fan.py` 从训练集人工描述抽分支弱标签，检查“弱标签 + 行业判据表”推出的等级与真值的一致率（≥ 85% 才用作监督）。
- 再用 S2 推理过程抽取，比较两种弱标签的质量。
- 然后对 S1 做 LoRA，让分支原语对齐弱标签，复跑 V4、V5。

## 附：已知坑
- vLLM 前缀缓存只在共享前缀完全相同时生效：图像和共享指令必须放在问题之前。
- H20 目前每卡只剩约 18 GB 显存：用 2 卡张量并行、`gpu_memory_utilization=0.17`，或 FP8 量化。
- 同一巡检点有多帧（-001、-002…），切验证集必须按巡检点分组，否则会泄漏。
