# Paper C 当前方向（2026-10-15）

> 一句话：借鉴 JEV 的“共享状态分支并发 + 类型化决策原语 + 校准评分”，把工业安全风险判断从“一个问题深想”改成“很多个简单问题并行判”，再做结构化有序聚合；只把不确定的那几个分支交给慢模型核验。

## 1. 动机

- InspecSafe-V1 的安全等级本身是可分解的：官方规则是“一张图有多个隐患时取最严重的那个”，而且**同一隐患在不同行业的严重度不同**（官方评测提示里的分行业判据表，见 `configs/inspecsafe_taxonomy.json`）。
  - 例：不戴安全帽在油气化工、输煤栈桥、冶金是 Level one，在隧道、电力是 Level two。
- 慢模型（Thinking / CoT）比快模型强，很大程度上是把“逐项检查隐患”串行做了一遍（推理深度）。JEV 的分支并发可以把同一件事改成并行（推理宽度）：图像只预填充一次，N 个隐患问题同时回答。
- 原蓝图里“单步模型受限于 TC⁰ 深度”的动机因此可以落地：对“多个浅层子判断取最大值”这类任务，单步模型缺的不是深度，而是“一个决策 token 要同时装下所有检查”的宽度。

## 2. 方法（四个模块，代码各自独立，见 `jevc/ideas/`）

| 模块 | 文件 | 做什么 |
| :--- | :--- | :--- |
| 1. 并行隐患原语 | `ideas/fanout_primitives.py` | 同一张图、同一段共享指令，并发问 J 个“是/否”隐患问题，读出每个分支 P(yes)。推理用 vLLM 前缀缓存实现共享预填充 |
| 2. 行业条件 noisy-OR 有序聚合 | `ideas/noisy_or_ordinal.py` | P(等级 ≥ k) = 1 − (1 − λ_k) · ∏_{j: sev_g(j) ≥ k} (1 − p_j)，g 为行业。有序、单调由结构保证，结果可解释到具体隐患。分支温度 / 偏置与泄漏项 λ_k 在验证集上用代价敏感 RPS 拟合 |
| 3. 分支级升级 | `ideas/branch_escalation.py` | 按“核验该分支能降低多少期望代价”（信息价值）排序，只把最值得的分支作为定向核验问题交给慢模型；同时保留整图级升级做对照 |
| 4. 推理链到分支的蒸馏 | `ideas/chain_to_fan.py` | 从慢模型推理过程（以及训练集人工描述）中抽取“提到了哪些隐患、是否存在”，作为分支弱标签；用于分支校准与后续 LoRA 训练 |

决策规则：在聚合后的分布上做代价敏感贝叶斯决策，cost(预测, 真值) = η·max(0, 真值 − 预测) + max(0, 预测 − 真值)，漏报权重 η > 1。

## 3. 和已有工作的区别（待查新确认，见 `validation_plan.md` V0）

- Gupta et al. (ICLR 2024)、Signed Rescue Routing：只能决定整个问题升不升级；我们决定升级哪个子判断，慢模型拿到的是定向核验问题。
- 问题分解 / 清单式评估：已有工作多为串行生成式分解；我们是共享预填充的并行判别原语 + 结构化有序聚合 + 分支级升级的组合。
- 并行推理（parallel thinking）类工作：并行的是生成推理链；我们并行的是校准的判别原语。

## 4. 从之前方案保留的部分

- 数据：InspecSafe-V1（主）、MMAD、SafeBuild-Bench；SafeSceneReason 只放附录。
- 救回 / 误伤分解、代价敏感 RPS 与命题 F* = P / (P + η(1 − P))、Bootstrap 置信区间。
- 基线：直接问等级（快模型）、Thinking 模型（慢模型）、MSP / 熵路由、Gupta et al.、SRR、单层线性探针。
- HBDP 隐状态探针降为可选的附加升级信号，暂不实现。
